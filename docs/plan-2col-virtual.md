# 계획 — 데스크톱 2열과 원고지 가상화

> 작성: 2026-08-11

## 0. 측정 — 지금 상태는 "느린" 게 아니라 "멈춘다"

단편소설 한 편 분량(공백 포함 14,008자, 272문단)을 넣고 원고지 쪽을 열어 봤다.

| | 값 |
|---|---|
| 조판 결과 | **82장** |
| 원고지 칸(`div`) | **16,400개** |
| 페이지 전체 DOM 노드 | **27,759개** |
| 원고 ↔ 원고지 전환 | **45초 넘게 렌더러 정지** (CDP 타임아웃, 재현됨) |

Swiper가 슬라이드를 전부 마운트하기 때문이지만, **근본 원인은 Swiper가 아니라 칸 개수다.** 한 장이 200칸이라 장 수에 그대로 비례한다. 슬라이더를 걷어내도 82장을 한꺼번에 그리면 같은 일이 벌어진다.

### 이 측정이 1번 계획을 바꾼다

데스크톱을 50/50 2열로 되돌리면 **원고지가 항상 화면에 있게 된다.** 지금은 원고를 쓰는 동안 원고지가 언마운트되어 있어 이 비용을 피하고 있을 뿐이다. 2열로 바꾸는 순간 **타이핑 한 글자마다 16,400칸이 다시 그려진다.**

그러므로 **가상화가 2열의 선행 조건이다.** 순서를 바꾸면 앱이 쓸 수 없게 된다.

---

## 1. 원고지 가상화 (먼저)

### 방식

Swiper를 걷어내고 **세로 스크롤 + 창(window) 렌더링**으로 바꾼다. 보이는 장과 위아래 한두 장만 DOM에 둔다.

- 라이브러리: [`@tanstack/react-virtual`](https://tanstack.com/virtual) (MIT, v3) — 헤드리스라 마크업을 우리가 그대로 쥔다. 이미 TanStack 스택이라 결이 맞는다
- 장 높이는 화면 폭에 따라 변하므로 `measureElement`로 실측한다. 고정값을 박으면 폭이 바뀔 때 어긋난다
- `overscan` 1~2장

기대치: 82장이든 200장이든 **DOM에 남는 칸은 3장치(600칸) 안팎**으로 일정해진다.

### 반드시 같이 처리해야 할 것

**1. 인쇄 — 가장 큰 함정이다.** 가상화는 보이는 것만 그린다. 그대로 두면 **인쇄물에 서너 장만 찍힌다.** 지금은 Swiper를 CSS로 풀어서 전 장을 뽑고 있는데, 그 수법이 통하지 않는다.
  - 해법: `beforeprint`에서 가상화를 끄고 전 장을 렌더 → `afterprint`에서 되돌린다. 82장을 그리는 동안 잠깐 멈추지만 인쇄는 원래 기다리는 동작이다
  - `window.matchMedia('print')`로도 잡을 수 있으나 Safari 지원이 고르지 않아 `beforeprint` 이벤트를 쓴다
  - **인쇄는 이번 변경에서 깨지기 가장 쉬운 지점이다. 반드시 실제 미리보기로 확인한다**

**2. 장 번호 막대.** `scrollToIndex`로 이동하고, 현재 장은 스크롤 위치에서 역산한다. 지금 만든 번호 막대 UI는 그대로 쓴다.

**3. 스크롤 컨테이너.** 지금은 페이지 전체가 스크롤된다. 2열이 되면 원고지 열만 따로 스크롤해야 하므로 컨테이너를 명시적으로 잡는다.

**4. Swiper 제거.** 의존성(4.6MB)과 `styles.css`의 인쇄용 `!important` 덩어리가 함께 사라진다. 키보드 넘김도 없어지므로 필요하면 새로 붙인다.

### 더 볼 수 있는 것 (선택)

칸 하나가 `div` 하나인 구조 자체를 줄이는 방법도 있다 — 한 줄을 `div` 하나로 그리고 격자는 배경으로 깔면 칸 `div`가 사라져 20배 줄어든다. 다만 칸마다 다른 정렬(온점은 구석, 병합된 부호는 좁혀 쓰기)을 표현하기 어려워진다. **가상화만으로 충분한지 먼저 보고, 모자라면 그때 검토한다.**

## 2. 데스크톱 50/50 2열 (가상화 다음)

### 방식

미디어 쿼리로 갈랐다가 지운 적이 있는데, **이번에는 다시 필요하지 않다.** 한 벌의 DOM을 두고 CSS로만 가린다.

```
<main class="grid lg:grid-cols-2">
  <div class={원고 보일 때 ''  : 'hidden lg:flex'}>   에디터 — 늘 마운트 </div>
  <div class={원고지 보일 때 '' : 'hidden lg:block'}>  원고지 </div>
</main>
```

- 에디터는 **항상 한 번만 마운트**된다. 쪽을 바꿔도 다시 만들지 않으므로 undo 히스토리도 살아남는다 (지금은 전환할 때 날아간다)
- 스위치는 좁은 화면에서만 뜬다 (`lg:hidden`) — 넓은 화면에선 둘 다 보이니 고를 것이 없다
- 제목·분량 바는 지금처럼 위에 가로로 걸친다

### 트레이드오프 — 미리 말씀드립니다

| | 지금(전체 폭) | 50/50 |
|---|---|---|
| 에디터 폭 | 1120px | 약 552px |
| 한 줄 글자수 | 78자 | **약 36자** |

처음 불편하다고 하셨을 때가 23자였으니 그보다는 낫지만, 78자에서 절반 아래로 줄어든다. 한글 산문에 편한 폭이 30~45자라 36자는 그 안에 들어오긴 한다.

**대안:** 60/40이나 55/45로 원고 쪽에 조금 더 주면 40자 안팎이 된다. 50/50으로 먼저 만들고 눈으로 본 뒤 정하는 편이 낫겠다.

## 3. 순서와 위험

1. **가상화** — 이것부터. 안 하면 2열이 앱을 멈춘다
2. **인쇄 확인** — 가상화 직후 실제 인쇄 미리보기로 전 장이 나오는지 본다
3. **2열 전환** — CSS만으로, 에디터는 한 번 마운트
4. **폭 비율 조정** — 실제로 써 보고 50/50이 좁으면 60/40

### 위험

- **인쇄가 조용히 깨질 수 있다.** 화면은 멀쩡한데 인쇄물만 몇 장 나오는 형태라 눈치채기 어렵다. 확인 단계를 따로 둔다
- **장 높이 실측이 어긋나면 스크롤이 튄다.** 폭이 바뀔 때(창 크기 조절, 쪽 전환) 재측정이 필요하다
- 지금 45초 멈춤은 **이미 있는 문제다.** 2열이 만들어내는 것이 아니라 드러내는 것뿐이다
